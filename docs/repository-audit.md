# Repository architecture audit — 2026-09-04

The product needs to turn sourced aviation data into a coherent 3D scene on web and native, then add live traffic and weather without blocking interaction. The useful boundaries are a generated static database, one shared computation core, platform renderers, and a long-running ingestion service. Most of the architecture supports those needs. The largest removable pieces were duplicate ownership and infrastructure left behind by earlier designs.

This review followed data and control flow across all major components. It is an architectural audit with targeted code and runtime verification, not a claim that every procedure or deployment configuration has been validated.

## What was removed

- The `minima` database table, its insertion pass, runtime row adapter, and types that existed to carry it around.
- A second runtime module tree compiled through `main.rs`, including broad library warning suppressions that hid the duplication.
- The Datadog relay route, cross-origin isolation headers and switches, and unused shared-memory debug fields.
- Duplicate PDF georeference and rasterization implementations in the two plate surfaces.
- Main-thread hold WASM initialization, duplicate hold state, and duplicate worker parameter declarations.
- Direct chart Cache API reads, the incorrect callback-property guard, and an unused worker subclass hook.
- The nonfunctional smoke command and its Playwright test package.

The database comparison retained all 11,171 resolved option records and 10,261 approach records. Removing the unused table reduced the original rebuilt database by 8,736,768 bytes. The later SQLite binding upgrade also rebuilds the database; logical records, rather than file bytes, are the compatibility check.

## Findings deliberately left for focused work

1. **Reference ties are still a domain decision.** The existing source order and alphabetical option order select different equally scored matches in 11 cases in the local dataset. Unifying them blindly can remove valid metadata: an attempted change for `KRIL/R26-W` lost its 3.50° vertical profile. Preserve behavior until the source identities and official plates settle each ambiguity. The resolver currently owns both decisions at build time.
2. **Source downloads are not published as one coherent set.** `scripts/download-data.sh` writes `approaches.json` before the matching CIFP download succeeds, and uses a shared `/tmp/cifp.zip`. The finished database is atomic, but an interrupted refresh can leave mixed inputs for a later manual build. A focused change should stage the related source set and test interruption/concurrent-run behavior. Do not simply remove data refresh from deployment builds without deciding how a verified database artifact is supplied.
3. **Native scene loads can accept superseded responses.** `AppFeature.loadSceneEffect` has neither cancellation nor a generation check, while `sceneLoadResponse` accepts success regardless of the current selection. Rapid airport/procedure changes need a TCA regression test on macOS, then one request owner as on the web.
4. **Native traffic session ownership needs explicit verification.** `TrafficSessionPool.resetSession` allocates a service and retains session IDs in its dictionary. Review window/store teardown and add a measured lifecycle check before deciding the release policy. Separate altitude resolution calls in native scene assembly may also be avoidable, but require marker/path parity checks before consolidation.
5. **Missing terrain is treated as elevation data.** Web terrain leaves holes in its source canvas; native `decodeElevationFeet` returns zero for absent/transparent tiles. Those paths can make missing coverage appear as sea level. Define a visible unavailable/partial state and test tile failures before changing surface geometry. Native terrain tile range/projection handling also needs date-line parity checks.

These concerns warrant work, but they do not justify deleting the computation core, daemon, native shell, or distinct rendering adapters. Their responsibilities are useful; the goal is to remove duplicated decisions and invalid assumptions within them.

## Verification

The full web/data suite passed all 153 tests. Rust workspace tests passed 114 core and 64 runtime tests, and the all-target workspace check passed. Formatting, lint, types, database rebuild/integrity, logical-record comparison, and production build also passed. Browser verification covered the home route, KSBS, and the historical KCRQ procedure. Scratch verification artifacts are under ignored `.tmp/` paths; browser CLI screenshots are in its user cache. Native build/runtime checks require macOS and Xcode; live OCI deployment/ingestion tests were outside this local audit.

The browser check covers the KSBS approach and protected holds with cross-origin isolation off. Before the temporary parity probe, the main thread made no WASM request. The built worker returned exactly the same 75 hold points and 108/181 protected-area points as the existing shared exports for the sampled hold. The plate skill dumped the shared composed scene and compared it with the preserved cycle-260806 FAA plate; its georeference control points reproduced their sourced coordinates. The final chart check loaded all 676 detail tiles, reported completion, and had no callback error. The service worker controlled the page. KCRQ retained its historical plate, training-only warning, and exclusion of current minimums. No uncaught browser errors or framework error overlays were observed in these checks.

Satellite rendering could not be exercised end to end because this local build has no Google Maps API key. Its shared PDF preparation was compiled and exercised through the flat renderer. Local Vercel analytics reports its expected unavailable deployment-only script; production telemetry delivery was not tested.

The SQLite crash was reproduced in both tests and the production server on Node 24 with version 11.10.0. Version 12 adds Node 24 to its supported build matrix ([upstream release notes](https://github.com/WiseLibs/better-sqlite3/releases/tag/v12.0.0)); 12.10.0 is pinned for the compatibility repair. Test isolation remains unchanged so future native failures remain visible.
