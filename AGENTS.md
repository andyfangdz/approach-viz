# AGENTS.md

## Project Snapshot

- Name: `approach-viz`
- Purpose: 3D visualization of FAA instrument approaches with airspace, terrain/surface context, live ADS-B traffic, and MRMS weather.
- Stack: Next.js 16 (App Router, React Compiler), React, TypeScript, react-three-fiber, SwiftUI, MetalKit, Composable Architecture, Swift Async Algorithms, Swift Collections, SwiftUI Introspect, GRDB.swift, Nuke, SQLite, Rust (Cargo workspace with `approach-viz-core` + `approach-viz-runtime` + `uniffi-bindgen-swift`), AWS SNS/SQS, Datadog.

## Maintenance Rule

- Keep this file current with code behavior.
- Any change to behavior, architecture, rendering, data sources, commands, validation, or dependencies must update `AGENTS.md` in the same PR/work item.
- Rendering behavior changes must also update the relevant `docs/rendering-*.md` files.

## Engineering Principles

- Fail loudly over silent fallbacks.
- Do not estimate, infer, or fabricate data values in place of sourced/computed values.

### Runtime Ops

- Provision SNS/SQS: `python3 scripts/mrms/setup_sns_sqs.py` — idempotently applies the MRMS product filter policy via `set_subscription_attributes` (a bare `sns.subscribe` cannot update an existing subscription's attributes), verifies the live filter policy and fails loudly on mismatch, and audits for stale MRMS-topic subscriptions/queues that bill one SQS request per SNS delivery even when unconsumed (`--audit-only` for read-only checks; `--cleanup-stale-subscriptions` / `--delete-stale-queues` to remove them). The runtime's SQS consumer acknowledges each received batch with a single `delete_message_batch` call instead of per-message deletes.
- Deploy runtime to OCI: `RUNTIME_MRMS_SQS_QUEUE_URL=... scripts/runtime/deploy_oci.sh ubuntu@<runtime-host>` (host argument is required; the script stages the Rust workspace members needed for `approach-viz-runtime` plus `Cargo.toml`/`Cargo.lock`, stamps runtime trace `service.version` from the local Git branch/SHA/dirty state, backs up the previous binary, and auto-rolls back on a failed post-deploy health check)
- One-shot ingest profile helper: `bash .agents/skills/runtime-profile-ingestion/scripts/profile_ingest_one_shot.sh --timestamp <ts> --repeats <n>`
- Live route latency profile helper: `bash .agents/skills/runtime-profile-live/scripts/profile_runtime_routes.sh --iterations 20`
- Live traffic stress helper: `bash .agents/skills/runtime-stress-traffic-live/scripts/stress_runtime_traffic.sh --requests 1200 --concurrency 40`
- Approach plate visual check (compare computed approach geometry to the real FAA plate): `bash .agents/skills/approach-plate-visual-check/scripts/dump_geometry.sh <ICAO>:<PROC_ID> ...` dumps the shared engine's geometry for real CIFP procedures in one command (extracts with `lib/cifp/parser` via `scripts/extract_geometry.ts`, composes segments through the shared `compose_approach_scene` export, and appends/removes the temporary Rust dump test automatically; `<ICAO>` alone lists an airport's procedures with per-leg path terminators). Then `scripts/fetch_plate.sh <ICAO> "<chart name>"` fetches/renders the plate (cycle auto-discovery skips FAA-pre-created future cycle directories) and `scripts/overlay_geometry.py` overlays the geometry directly on the georeferenced plate (GPTS/LPTS control points; `scripts/plot_geometry.py` for a schematic side-by-side — both color segments by label prefix so transitions can't collide with the missed-approach red). See `.agents/skills/approach-plate-visual-check/SKILL.md`. Use when changing approach-path rendering or when a procedure looks wrong versus the chart.

## Current Behavior (Keep in Sync)

- Historical training fixtures preserve two decommissioned procedures with validated SHA-256 hashes: `fixtures/historical-approaches/ksbs-r32-z.cifp-260806.json` captures `KSBS / R32-Z` from cycle `260806`, and `fixtures/historical-approaches/kcrq-r24-x.cifp-251225.json` captures the non-RNP `KCRQ / R24-X` (`RNAV (GPS) X RWY 24`) from cycle `251225`, including its two OCN-transition RF legs. Each schema-v2 fixture also identifies a versioned geo-referenced PDF under `fixtures/historical-approaches/plates/` by D-TPP cycle, plate filename, byte count, and SHA-256; fixture loading rejects missing/corrupt PDFs or PDFs without `/GPTS` and `/LPTS`, and `next.config.ts` explicitly traces the fixture JSON/PDF files into server deployments. `build-db` inserts each fixture only when current CIFP lacks that same airport/procedure ID (current FAA always wins), marks the SQLite/API source as `historical` with its captured cycle, and embeds approach-specific waypoint JSON. Web and native selectors/title/legend identify active fallbacks as historical, decommissioned, and training-only. Historical geometry never inherits current minimums, missed-instruction, vertical-profile, or live plate matching; the web scene instead receives only its fixture's preserved plate metadata for training draping. `KSBS / R32-Z` remains a configured default, while `KCRQ / R24-X` is only an available historical option and does not change startup defaults.
- AVMR brick merging keys on `{phase, surface_phase, 5 dBZ-quantized dbz}` — `surface_phase` is keyed because the default client phase mode colors by it, so bricks never blend cells across a surface rain/snow boundary — and each brick ships the true maximum `dbz_tenths` over its merged cells rather than the quantized grouping bucket, so displayed intensity is never understated.

- Worker-first execution: approach altitude resolution, scene composition, and path/hold geometry, MRMS decode/prepare, traffic ingest/merge/recompute, selector filtering, and chart tile streaming run in workers via Comlink typed proxies; no synchronous compute fallback. The approach worker is a thin WASM adapter over the shared Rust engine, and its output arrays transfer to the main thread via `Comlink.transfer()` (zero-copy). The web `ApproachPath` overlay keys composed worker state to the selected airport and procedure and resets it during render so a selection change never paints the old procedure at the new airport.
- ADS-B overlay polling: initial full-history query on context reset (`historyMinutes`), then live-only primary polls plus targeted `historyHexes` follow-up backfill when departed trails are enabled.
- ADS-B runtime payloads with `error` metadata are treated as poll failures in the traffic worker (no silent empty merge), and traffic worker request timeout budget is `12s`.
- ADS-B history-backfill follow-up failures no longer disappear silently: the web traffic worker surfaces `historyBackfillError` through the worker result into the traffic debug panel, and the native iOS `TrafficService` logs the failure and keeps the affected hexes pending so the next poll retries them.
- The `/api/faa-plate` proxy serves a hash-validated local historical PDF before consulting FAA when the normalized D-TPP cycle/filename matches a preserved fixture key. All responses use a strong `ETag` derived from a SHA-256 of the served PDF bytes (`"sha256-<hex>"`) rather than an upstream CDN validator, set `Content-Length`, and answer a matching `If-None-Match` (RFC 9110 weak comparison, `W/` prefixes and `*` handled) with `304 Not Modified` and no body; live responses also forward `Last-Modified`. Live FAA reads remain bounded: one `AbortSignal.timeout` (15s) covers connect plus body read, and the body is drained through a byte-counting reader capped at 16 MB (the counter is authoritative because upstream `content-length` may be absent or wrong). Upstream timeouts return `504`, oversize/failed reads return `502`, and a non-`ok` upstream still returns `404`.
- The `/api/traffic/adsbx` proxy validates query params before forwarding: present-but-malformed `radiusNm`/`limit`/`historyMinutes` return 400, finite out-of-range values are clamped to the runtime bounds, `format` must be a known value, and `historyHexes` entries must be hex identifiers (max 400). The Rust runtime applies the same reject-malformed/clamp-out-of-range policy and also rejects non-finite lat/lon (`NaN` included) on weather and traffic endpoints.
- The runtime HTTP router applies a 30s per-request `TimeoutLayer` (504 on expiry), and the weather volume/echo-tops handlers clone the latest scan `Arc` and release the snapshot read lock before FlatBuffers encoding so ingest writers are never blocked by slow queries. CPU-heavy runtime paths run on the Tokio blocking pool instead of async workers: per-request volume/echo-tops window filtering + FlatBuffers encoding, and MRMS scan snapshot assembly during ingest (per-level filter/gather/phase passes, full-grid echo-top scan with a no-signal fast skip, and counting-sort tile grouping).
- The web MRMS reflectivity volume renders as a single raymarched box (`app/scene/nexrad/NexradVolumeRaymarch.tsx`): the WASM binding (`decode_and_prepare_mrms`) rasterizes the declutter-selected bricks inside Rust (`crates/approach-viz-core/src/mrms_render.rs::build_volume_texture`) into a dense RG8 3D texel grid (R = whole dBZ with 0 = empty and strongest-return-wins on overlap, G = phase code bled into adjacent empty texels so trilinear filtering does not tint echo edges toward rain; corrected-feet altitudes with curvature pre-applied; horizontal cells coarsen by whole footprint multiples to stay within 256 per axis; ~500 ft altitude bins capped at 96) plus placement metadata and altitude-guide extents, and the fragment shader marches it front-to-back (back faces + depth-read-only so the camera can sit inside; resolution-aware 24-384 jittered steps; optical depth integrated over unscaled NM so vertical exaggeration changes shape but not opacity; opacity slider maps to extinction) with sample colors from a nearest-filtered band-by-phase LUT texture built from the shared band tables. Draw cost is per-pixel instead of per-voxel — the former base+glow instanced meshes (~2 GPU instances per brick) are gone from the web renderer, and the `declutterIndices` → `validIndices` → payload-column pairing still does not exist in TypeScript (the rasterization and its regression tests live next to the old join in `mrms_render.rs`). Known limitation: a ray is depth-tested where it exits the volume, so opaque geometry standing inside the box (a ridge in satellite mode) hides the whole ray rather than only the weather behind it. Echo-top tiles remain instanced with direct `instanceMatrix.array` writes, the debug-panel phase tally still comes from the MRMS worker result, and the worker's volume payload remains metadata-only. The native iOS/macOS renderer still draws GPU-instanced voxel boxes from the shared `build_render_volume` flat-column join; porting the raymarcher to Metal is a planned follow-up.
- The WASM AVMR/AVET decoders validate FlatBuffers column presence and length once at view construction, so the per-voxel prepare/cross-section/render-join loops carry no Option or length handling; a missing or length-mismatched column fails the poll with an explicit error instead of zero-filling or trapping.
- Runtime traffic "current aircraft" staleness window is `60s` (`CACHE_CURRENT_STALE_MS`); responses expose stale/freshness markers via `x-approach-viz-traffic-stale-current` and `x-approach-viz-traffic-snapshot-age-ms` headers (proxy passthrough enabled), and JSON payloads include `staleCurrent` + `snapshotAgeMs`.
- Ground reflectivity mosaic (web-only layer `mosaic`, `Surface Mosaic`, default off) draped beneath the 3D volume so storms read as standing on a weather surface. `Surface Mosaic Product` (URL `mosaicProduct=composite|base`, default `composite`) selects the column reduction: `composite` is the column max over every MRMS level, `base` is the lowest-altitude echo in each column (MRMS levels are altitude-based, so this takes the lowest level that has data rather than a fixed index, ties broken by the stronger return). The raster footprint is product-independent, so switching re-runs only the Rust prepare pass over the cached binary and does not rebuild the drape mesh; the reported max dBZ is taken over the finished raster so base mode reports what it draws. It needs no new product or request — the layer rides the same volume poll as the 3D volume and the cross-section, and `crates/approach-viz-core/src/mrms_render.rs::build_composite_surface` reconstructs source-grid indices from brick centers (the runtime's regular lat/lon grid makes `x_nm / footprintXNm` a grid column index up to a constant offset that cancels against the per-payload minimum; a non-positive footprint or an implausible raster size fails loudly). The raster is trimmed to the echo bounding box, row-major with `x` fastest, row 0 on the `-z` edge. It honors the dBZ threshold and phase mode but deliberately ignores declutter (a plan view of the whole column, not an altitude band). The worker colors it into RGBA through the shared band tables in `app/scene/nexrad/nexrad-colors.ts` (extracted from `nexrad-render.ts` so it is `three`-free and worker-safe), bleeds edge RGB into adjacent empty cells so linear filtering does not fringe echo edges dark, and transfers the finished buffer; `app/scene/nexrad/NexradSurfaceMosaic.tsx` uploads it as a `DataTexture` over an explicit local-NM grid mesh with per-vertex earth-curvature drop for satellite/3D map modes. The base surface is user-selectable (`Surface Mosaic Base` in the Options panel, URL `mosaicBase=flat|terrain`, default `terrain`): `flat` pins the sheet to field elevation, `terrain` samples Terrarium elevation per vertex (~1 NM segments, 32-256 per axis) so echoes are not sliced by ridges. The mosaic carries a negative polygon offset because it is a ground decal — within depth precision of the surface beneath it the depth test would otherwise speckle, and the offset is slope-aware where a fixed lift is not. Clearance is 200 ft in terrain/plate/map modes (same Terrarium raster as the drape) and 500 ft in satellite/3D map modes, where the ground is Google's sub-meter 3D tiles and the ~0.25 NM drape smooths ridges. The drape's elevation raster is a separate coarser fetch from the terrain wireframe's — zoom 8 over the full weather radius (~25 tiles, ~0.25 NM/px) rather than the wireframe's z10/50 NM grid — keyed to the reference point rather than the echo bounding box, so it survives storm movement and does not depend on the terrain layer being visible. Missing tiles fall back to field elevation instead of sea level, and a total tile failure draws flat and reports `terrain-unavailable` in the debug panel rather than passing a flat sheet off as terrain. The native iOS/macOS renderer does not draw this layer yet. See `docs/rendering-weather-volume.md`.
- MRMS altitude guides close into a reference box: the 5,000-ft rings are joined by corner posts running from the surface to the top ring.
- Layer defaults (`DEFAULT_LAYER_STATE`): `approach`, `airspace`, `adsb`, `probsevere`, `guides` = on; `mrms`, `mosaic`, `echotops`, `slice`, `holdareas`, `obstacles` = off.
- Published obstacles (web-only layer, default off): `download-data` fetches the FAA daily Digital Obstacle File (`DAILY_DOF_DAT.ZIP`), `lib/dof/parser.ts` parses the fixed-width `DOF.DAT` (throws on malformed coordinates/heights, supports negative below-sea-level AMSL; records with no published AMSL height are skipped with a logged count), and `build-db` loads all ~647k records into `obstacles` + `obstacle_rtree` with the DOF currency date in `metadata`. Obstacles are not in the base scene payload: `app/scene/ObstacleOverlay.tsx` fetches on demand through the `loadObstaclesAction` server action using the Options-panel `Obstacle Range` (5–80 NM, default 30) and `Obstacle Threshold` (0–2,000 ft AGL, default 200 ft — sectional charting threshold) controls; obstacles penetrating the FAA TPP 67:1 plan-view charting surface from the runway centerlines (`lib/obstacles/plate-significance.ts`) are always included regardless of the threshold — decluttered TPP-style to the locally-highest obstacle within 1 NM, since the 67:1 rule only marks obstacles "considered for charting" and high terrain otherwise sweeps in every rooftop on a ridge — and responses are capped at 2,500 (charting-surface penetrators kept preferentially, then tallest by AMSL) with the uncapped `totalCount` surfaced as a "Showing tallest X of Y" note (no silent caps). Rendering: shafts from ground (`AMSL - AGL`) to top in the absolute-MSL frame, per-type instanced tips mapped by `app/scene/obstacle-shapes.ts` (towers → cone, windmills → rotor ring, buildings → box, tanks/stacks/silos → cylinder, other → octahedron; lighted `#ff6b6b`, unlit `#ffb84d`, ≥1,000 ft AGL tips scaled up) with every glyph top-anchored at the published obstacle top so markers never render taller than the obstacle, the highest obstacle in range drawn TPP-style with a larger glyph + bolder label, plus chart-style `AMSL (AGL)` labels (TPP `±` suffix on unverified elevations) on the 12 tallest behind a `Show Obstacle Labels` toggle (default on). The native iOS/macOS renderer does not draw this layer yet. See `docs/rendering-obstacles.md`.
- `/overview` (`app/overview/`) is an interactive architecture briefing page: section content lives as data in `overview-content.ts`, rendered by `OverviewClient.tsx` with an interactive SVG system map, MRMS-pipeline/worker-topology/plate-projection diagrams, and a dBZ color-LUT legend that mirrors the band tables in `app/scene/nexrad/nexrad-types.ts`. File references (chips, inline repo paths, code-block titles) link to GitHub `master` via `app/overview/github.ts`, and embedded code excerpts get lightweight regex-based syntax highlighting via `app/overview/syntax.tsx` (no highlighter dependency). The page provides its own scroll container (the app shell pins `<body>` with `overflow: hidden`/`touch-action: none`) and its `.ov-header` must override the global `header` element styles from `App.css`. Keep its content in sync with architecture changes alongside this file.
- MRMS phase-mode default is `surface` (`Surface Precip Type`); `thermo` is optional.

- Anti-slop Oxlint (`npm run lint:anti-slop`, also part of `npm run lint`, `.oxlintrc.json`) uses the `oxlint-plugin-anti-slop` Git dependency (`git+https://github.com/dmmulroy/anti-slop.git#446268e5d15baa968eaec669ff65358d36ae6259`) to scan TypeScript/JavaScript for low-evidence patterns (`unknown`/`object` contracts, undocumented type assertions, ad hoc `typeof` narrowing, empty-object spreads, module mocks). `no-runtime-typeof` allows `typeof` only inside type predicates (`allowInTypeGuards: true`); JSON I/O is parsed through `lib/parse-like.ts` (`JsonValue` / `parseJsonValue`) rather than `unknown`. The plugin ships TypeScript (`exports: ./src/index.ts`), and Node refuses to strip types under `node_modules`, so the lint scripts load Oxlint through `node --import tsx`. Keep `package-lock.json` `resolved` on `git+https://` (npm may rewrite it to `git+ssh://` on fetch). The TypeScript plugin still needs Node `^20.19 || >=22.18`.
- `scripts/download-data.sh` pins the Class B/C/D airspace GeoJSON source to a specific commit of `drnic/faa-airspace-data` and validates each payload parses as GeoJSON before installing it; the CIFP parser fails loudly (throws) on malformed DMS coordinates instead of fabricating 0,0. The script authenticates its `api.github.com` release lookup with `GITHUB_TOKEN` when set (the macOS native workflow passes `github.token`) so shared CI runners do not hit anonymous rate-limit 403s; release-asset downloads stay unauthenticated because the signed CDN redirect rejects forwarded `Authorization` headers.
- Approach-path engine sources live in `crates/approach-viz-core/src/approach_path/` (split into `types`/`altitudes`/`geometry`/`holds`/`compose`/`support` modules with the public API re-exported from the module root). Course-from-fix legs (`FA`/`FC`/`FD`/`FM`) project an outbound apex from the originating fix along the published course (distance from the leg for `FC`/`FD`, default fallback otherwise). A teardrop/course-reversal (course-from-fix outbound + a no-fix `CI`/`VI` intercept, for example `KDDC I14` `FLACK` at `OWENJ`) renders as a single smooth circular arc through the outbound fix and the outbound apex that rolls out tangent onto the final approach course at an interior point — one continuous curve with no straight outbound leg. The roll-out point is the tangent point of the circle with the course line (`course_reversal_rollout_point`), not the course fix itself; `build_arc_through_three_points` draws the arc from the outbound fix through the apex to that tangent point and the transition terminates there. `compose_approach_scene` appends the final approach's first course-carrying fix leg (the FAF/localizer leg) to a transition ending in `CI`/`VI` to supply the course; that appended leg is consumed by the reversal and not drawn as a separate inbound segment. Web and native clients are thin adapters over that export. As an engine fallback when no roll-out fix is available, a terminal `CI`/`VI` after a course-from-fix leg is completed as a single broad, continuous turn (its own wider radius band, not the tight `VI` heading-stub radius) plus a mirrored inbound leg, instead of dead-ending at a sharp spike/stub. A plain course-from-fix leg with no reversal still renders as a straight outbound segment instead of collapsing onto the fix. A DME arc (`AF`/`RF`) that terminates a transition by joining an inbound course (for example the `KDDC I14` `POKPE`/`EARPP` 14 DME arcs onto `WEROM`) rolls out of the arc with a lead turn near the fix — matching the charted lead radial — instead of cornering sharply onto the inbound course: `build_dme_arc_lead_turn` builds a turn-radius fillet (`DME_ARC_LEAD_TURN_RADIUS_NM`) tangent to both the DME arc and the inbound course line, the arc is truncated at the lead point, and the transition rolls out established on the inbound course near the fix (continuing straight to the fix when the roll-out lands short of it). The fillet is selected by enumerating all four tangency combinations (center on either side of the inbound course line × internal/external tangency to the arc) and keeping the gentlest turn (smallest sweep, well under a half-circle) that enters tangent to the arc in the direction of travel (no cusp) and rolls out heading toward the fix — so both arc approach directions (`POKPE`'s clockwise arc and `EARPP`'s counter-clockwise arc) get a clean lead turn rather than only one side. The same `compose_approach_scene` pass that appends the FAF/localizer leg to `CI`/`VI` transitions also appends it to `AF`/`RF` transitions to supply the inbound course; the appended leg is consumed by the lead turn and the inbound course itself is drawn by the owning segment. An `AF`/`RF` arc that is not followed by an inbound course leg still renders as the full arc to its terminating fix. A `PI` (procedure turn) leg renders the full charted 45°/180° course reversal anchored at its fix (for example `KACK S24` at the `ACK` VOR): outbound on the reciprocal of the inbound course, 45° turn onto the published excursion (barb) course, straight excursion leg, 180° reversal, then an intercept back onto the inbound course with a tangent roll-out ending established on the course outbound of the fix (`build_procedure_turn_points`, proportions standardized by the `PROCEDURE_TURN_*` constants within the CIFP remain-within limit); the inbound course comes from the following `CF` back to the same fix (which draws the inbound course itself) or is derived from the excursion course + reversal direction, a `PI` whose course data is missing or self-contradictory (published reversal direction disagreeing with the side the published courses imply) keeps the draw-to-fix behavior, and a `PI` with no following course leg extends the inbound leg to the fix. Hold racetrack sizing is shared too: `resolve_hold_leg_length_nm` uses a published leg distance as-is, and otherwise flies the published hold time (parsed from the ARINC 424 "T"-coded route-distance field into `holdTime` minutes by the CIFP parser) — or the standard pattern timing (1 min at or below 14,000 ft MSL, 1.5 min above) when neither is published — at the FAA maximum holding airspeed for the hold altitude (AIM 5-3-8: 200/230/265 KIAS tiers) converted to TAS with the ~2%-per-1,000-ft rule, replacing the old fixed 4 NM fallback; web (`HoldPattern.tsx`) and iOS (`ApproachMetalRenderer.swift`) both resolve through that engine export, and time-published holds label the timing alongside the derived length (e.g. `1MIN (3.6NM)`). An optional `Hold Protected Areas` layer (default off, web `holdareas` + native `holdAreas`) renders each hold's protected airspace per FAA Order 8260.3F (TERPS) chapter 16 from the shared `build_hold_protected_area` export: the pattern number comes from table 16-3-1 (RNAV column) via the AIM 5-3-8 speed tier for the hold altitude, the primary boundary follows the section 16-6-2 construction sequence (figure 16-6-1) with the published table 16-6-1 dimensions (transcription validated against the table's Total Length/Width checksums; left-hand patterns mirror per 16-6-2; legs longer than the pattern's L-M stretch the body as an approximation of the section 16-13 leg-length areas), and a 2 NM secondary band surrounds the primary per paragraph 16-2-4.b.
