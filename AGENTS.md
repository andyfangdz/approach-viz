# AGENTS.md

## Project Snapshot

- Name: `approach-viz`
- Purpose: 3D visualization of FAA instrument approaches with airspace, terrain/surface context, live ADS-B traffic, and MRMS weather.
- Stack: Next.js 16 (App Router, React Compiler), React, TypeScript, react-three-fiber, SwiftUI, MetalKit, Composable Architecture, Swift Async Algorithms, Swift Collections, SwiftUI Introspect, GRDB.swift, Nuke, SQLite, Rust (Cargo workspace with `approach-viz-core` + `approach-viz-runtime` + `uniffi-bindgen-swift`), AWS SNS/SQS, Datadog.

## Maintenance Rule

- Keep this file current with code behavior.
- Any change to behavior, architecture, rendering, data sources, commands, validation, or dependencies must update `AGENTS.md` in the same PR/work item.
- Rendering behavior changes must also update the relevant `docs/rendering-*.md` files.

## Engineering Principles

- Fail loudly over silent fallbacks.
- Do not estimate, infer, or fabricate data values in place of sourced/computed values.

## Core Commands

### App/Data

- Install deps: `npm install`
- Download source data: `npm run download-data`
- Build SQLite DB: `npm run build-db`
- Full data refresh: `npm run prepare-data`
- Dev server: `npm run dev`
- Production build: `npm run build`
- Production server: `npm run start`
- Native iOS bridge + project generation: `npm run build:ios`
- Force native iOS bridge + project regeneration: `npm run build:ios:force`

### Quality

- Format check: `npm run format:check`
- Lint: `npm run lint`
- Typecheck: `npm run typecheck`
- Tests (parser + geometry + layers + MRMS + worker lifecycle + API routes): `npm run test`
- Runtime live integration tests: `npm run test:integration:runtime`

### Service Worker

- Build service worker: `npm run build:sw`

### Rust / WASM

- Workspace check: `cargo check`
- Runtime crate check: `cargo check -p approach-viz-runtime`
- Core crate check: `cargo check -p approach-viz-core`
- Build WASM + copy to `public/`: `npm run build:wasm` (needs `wasm-pack`; if wasm-pack falls back to a system `wasm-opt`, it must be binaryen ≥ 117 — Ubuntu apt's binaryen 108 emits a broken artifact whose externref table cannot grow, trapping at module init)

### Runtime Ops

- Provision SNS/SQS: `python3 scripts/mrms/setup_sns_sqs.py`
- Deploy runtime to OCI: `RUNTIME_MRMS_SQS_QUEUE_URL=... scripts/runtime/deploy_oci.sh ubuntu@<runtime-host>` (host argument is required; the script stages the Rust workspace members needed for `approach-viz-runtime` plus `Cargo.toml`/`Cargo.lock`, stamps runtime trace `service.version` from the local Git branch/SHA/dirty state, backs up the previous binary, and auto-rolls back on a failed post-deploy health check)

- Live route latency profile helper: `bash .agents/skills/runtime-profile-live/scripts/profile_runtime_routes.sh --iterations 20`
- Live traffic stress helper: `bash .agents/skills/runtime-stress-traffic-live/scripts/stress_runtime_traffic.sh --requests 1200 --concurrency 40`
- Approach plate visual check (compare computed approach geometry to the real FAA plate): `bash .agents/skills/approach-plate-visual-check/scripts/fetch_plate.sh <ICAO> "<chart name>"` then dump engine geometry (`.agents/skills/approach-plate-visual-check/templates/dump_geometry.rs.txt`) and plot with `scripts/plot_geometry.py`. See `.agents/skills/approach-plate-visual-check/SKILL.md`. Use when changing approach-path rendering or when a procedure looks wrong versus the chart.

## Current Behavior (Keep in Sync)

- Runtime endpoints:
  - `GET /v1/weather/volume` -> `application/vnd.approach-viz.mrms.v5` content-type (wire format AVMR v5, FlatBuffers) (legacy alias `/v1/volume`)
  - `GET /v1/weather/echo-tops` -> JSON by default; AVET binary with `Accept: application/vnd.approach-viz.echo-tops.v3` content-type (wire format AVET v3, FlatBuffers) (legacy alias `/v1/echo-tops`)
  - `GET /v1/traffic/adsbx` -> JSON or binary (`format=binary`, `application/vnd.approach-viz.traffic.v4` content-type, wire format AVTR v4, FlatBuffers)
- Native iOS rewrite foundation lives under `ios/`: a scene-first SwiftUI + MetalKit shell backed by the same `approach-viz.sqlite` bundle copied into the app during Xcode builds. The earlier RealityKit renderer has been removed.
- The native iOS shell now uses `GRDB.swift` for bundled read-only SQLite access, `Nuke` for Terrarium tile fetch/decode caching, and a TCA root reducer in `ios/ApproachViz/App/AppFeature.swift` instead of the removed `AppModel.swift` observable-object view model. FAB-triggered detail panels are now native SwiftUI overlays rather than a UIKit-hosted panel library.
- The generated iOS project now disables `ENABLE_APP_INTENTS_METADATA_GENERATION` and explicit module builds (`SWIFT_ENABLE_EXPLICIT_MODULES=NO`, `CLANG_ENABLE_EXPLICIT_MODULES=NO`) for native scripted builds so Xcode 26 does not emit Point-Free package dependency-scan warnings during `npm run test:ios`. The app target still links `AppIntents.framework`, its pre-build copy/verification scripts declare explicit inputs/outputs for dependency analysis instead of running unconditionally every build, and `scripts/test-ios.sh` filters the remaining known third-party `appintentsmetadataprocessor` “No AppIntents.framework dependency found” warning line that Xcode still emits for some Swift package frameworks during test builds.
- Approach-path domain logic now has a single implementation in `crates/approach-viz-core/src/approach_path.rs`. Web uses that engine through WASM in `app/scene/approach-path/approach.worker.ts`, and iOS uses the same engine through UniFFI in `ios/ApproachViz/Scene/ApproachPathGeometry.swift`. There is no remaining TypeScript or Swift fallback implementation for altitude resolution, path geometry assembly, or hold geometry generation.
- Native iOS rendering currently covers airport selection, approach selection, a dark-mode Terrarium-backed terrain wireframe/fill, Class B/C/D airspace volumes with triangulated top caps, optional bottom caps, and top/side outlines, runway geometry, waypoint point sprites with label overlays positioned from Rust-resolved leg altitudes, sampled transition/final/missed path segments from the shared Rust engine, separate Rust-generated hold-pattern overlays plus hold annotations, a live ADS-B traffic layer with current aircraft markers, optional current-track callsign labels, and departed-history trails built from the shared Rust traffic merge/render state, and an optional MRMS weather volume layer (default off) rendered as GPU-instanced translucent voxel boxes. The displayed final path extends through the first missed-approach fix when that fix resolves, while hold legs are kept out of the main path segments. Native scene loading now also reads bundled external approach reference JSON (`public/data/approach-db/approaches.json`) so matched minimums/VDA rows and parsed missed-climb requirements can influence native vertical-profile rendering. The Metal renderer now has a custom gesture camera with one-finger orbit, two-finger pan, pinch zoom, initial target/distance derived from scene focus bounds, a tighter camera-reset fit for phone-sized startup views, focus-bounds priority on final/missed procedure geometry plus missed holds over transition-only overlays, a default azimuth aligned with the web scene's southeast-looking startup camera, corrected horizontal drag direction for orbit yaw, display-max frame-rate requests instead of a 30 FPS cap, on-demand redraws driven by scheduled `setNeedsDisplay()` invalidation instead of synchronous gesture-time `draw()` calls, indexed Metal airspace triangle/line meshes instead of fully expanded raw airspace primitive arrays, cached Metal monochrome SDF text-atlas label quads instead of a UIKit overlay, shader-applied label colors instead of precolored bitmap text, stable screen-space label decluttering that prefers already-visible labels while the camera moves, dedicated dynamic Metal traffic line/point layers so traffic polls do not rebuild cached static scene buffers, and an internal renderer framework split across `ApproachMetalRenderer.swift`, `ApproachMetalRenderEngine.swift`, `ApproachMetalCameraController.swift`, `ApproachMetalRenderTypes.swift`, and `ApproachMetalTextAtlas.swift` so dirty-flag invalidation, camera state, cached uniforms/labels, buffer-backed draw layers, atlas-backed text quads, and a debug render-stats pipeline are explicit rather than ad hoc. It also keeps the web-style 3.0x startup vertical scale, thicker solid path prisms, dashed-prism rendering for below-minimums and hold overlays, brighter runway glyphs/labels, runway prisms lifted into the same absolute-MSL vertical frame as terrain/path geometry so high-elevation airports like `KSBS` do not render underground, centralized absolute-MSL `y` conversion helpers for native terrain/runway/waypoint/hold/path placement, web-matched surface-floor clamping for airspace sectors whose source floor is at or below sea level, a separate non-depth-writing translucent pass for airspace caps/walls so overlapping sectors do not read opaque, corrected label projection in view-point space so waypoint/hold labels track their anchors correctly on Retina simulators, direct consumption of the Rust path builder's `verticalLines` plus `turnConstraintLabels` outputs instead of synthesizing extra guide lines in Swift, the same absolute-altitude contract into the shared Rust hold builder that the web renderer uses, a shared Rust local-axis sign convention for path geometry plus waypoint/runway/hold overlay anchors, and an absolute-MSL vertical frame for native terrain plus waypoint/runway/hold/path geometry so those elements match the web renderer's altitude convention. Camera/framing parity with the web renderer is still incomplete. Terrain tile fetches tolerate per-tile failures instead of dropping the entire surface. The native app currently defaults to `KTEB` / `H06-Z` for an airspace-heavy startup view.
- The Metal scene host now renders directly into a raw `MTKView` wrapped by a platform-specific SwiftUI representable, while shared scene plumbing in `ios/ApproachViz/Scene/PlatformUI.swift` abstracts colors, fonts, image decoding, graphics-context setup, redraw invalidation, and max-frame-rate lookup so the renderer core is no longer hard-wired to UIKit. iOS keeps one-finger orbit, two-finger pan, and pinch zoom; the native macOS branch maps mouse-drag orbit, two-finger trackpad pan via scroll-wheel events, and magnification-to-zoom, with desktop orbit using the same vertical inversion as iOS but a non-inverted horizontal drag direction. Shared native pan now translates the camera target strictly across the ground plane (`x`/`z`) instead of moving it along the camera's local vertical, and its forward/backward ground-pan scale is normalized against the camera's vertical view component so near top-down views do not accelerate unnaturally. The shared text-atlas raster path now also uses the correct flipped AppKit graphics context so macOS label glyphs stay upright and match the iOS/web label orientation.
- The native MRMS weather layer polls `https://approach-runtime.andyfang.app/v1/weather/volume` (AVMR v5 binary, `minDbz=5`, `maxRangeNm=120`) and — when echo tops are enabled — `/v1/weather/echo-tops` (AVET v3 via `Accept: application/vnd.approach-viz.echo-tops.v3`) every 120 seconds with a 10-second retry; failures are tracked per payload so one feed going down does not block the other, and the last good data stays on screen. Decode/prepare runs through the shared Rust engine's `decode_and_prepare_mrms_volume` (now also building the optional cross-section grid and altitude-guide extents) and `decode_and_prepare_echo_tops` UniFFI exports. The poll gate matches the web (`mrms || echotops`); the slice rides on the volume fetch. Rendering covers the full web overlay surface: base + glow voxel passes (one instanced buffer drawn twice through per-pass `{density, softCap, opacity}` fragment params), flat-shaded instanced echo-top tiles at 18/30/50 dBZ threshold altitudes, altitude-guide rings/labels every 5,000 ft sized to rendered weather extents, an in-scene translucent slice plane with ground axis line, and a SwiftUI vertical-slice HUD panel (`CrossSectionHUDView`) with the heatmap, altitude ticks, and echo-tops summary. The prepare-pass dual index space is joined inside Rust (`crates/approach-viz-core/src/mrms_render.rs`) so clients never pair `declutterIndices`/`validIndices`/payload columns themselves — the web client consumes the same join through the WASM `decode_and_prepare_mrms` binding; Rust returns unscaled-NM columns and each client applies vertical scale at instance build (Swift) or via the scene group transform (web), so vertical-scale and opacity changes need no Rust round trip. Prepare-only option changes (threshold, phase mode, declutter, slice heading/range) re-run the Rust prepare pass over the cached volume binary through a debounced re-prepare effect — no network refetch (the web worker's re-prepare path). The weather layers are dynamic Metal layers with their own invalidation flag like traffic (static scene buffers stay cached). The Layers panel toggles `MRMS Volume`, `Echo Tops`, `Vertical Slice`, and `Altitude Guides` (guides default on, the rest off, matching web `DEFAULT_LAYER_STATE`); the Options panel exposes the web's weather controls (phase detection `Thermodynamic`/`Surface Precip Type`, declutter `All/Low/Mid/High`, threshold 5–60 dBZ, opacity 5–100%, slice heading 0–359°, slice range 30–140 NM) plus status/error reporting; macOS keeps the `Cmd-Shift-W` MRMS shortcut.
- The native iOS traffic layer polls `https://approach-runtime.andyfang.app/v1/traffic/adsbx` directly in AVTR binary mode every 5 seconds, uses an initial full-history request plus periodic full refreshes and targeted `historyHexes` follow-up backfill like the web overlay, resolves traffic altitude placement against the selected airport plus bundled elevation-only airports within 80 NM, and rebuilds marker/trail scene geometry from the shared Rust `TrafficStateHandle` UniFFI object when polls succeed or the vertical scale changes. Traffic geometry now lives in dedicated dynamic Metal line/point layers, so live traffic updates stay visible during orbit/pan/pinch gestures without forcing a full rebuild/upload of cached terrain, airspace, runway, waypoint, or approach-path buffers.
- Native iOS shell state now flows through TCA actions/state rather than ad hoc view-model mutation: airport/approach selection, FAB panel routing, layer toggles, vertical scale, error state, and live traffic lifecycle all live in `AppFeature.State`. The traffic poll loop is driven with `AsyncTimerSequence`, selector preview pinning uses `OrderedSet`, and the airport filter field uses `SwiftUIIntrospect` to disable UIKit autocorrect/capitalization/smart punctuation behaviors.
- The native detail view now exposes FAB-driven Selectors, Layers, Options, and Debug panels through a SwiftUI bottom-sheet overlay instead of keeping controls in a split view, fixed inset, or UIKit-hosted panel library. The Selectors panel now uses an explicit segmented `Airports` / `Approaches` mode instead of one long mixed list: the airport mode contains the filter field plus the first 200 airport matches (keeping the selected airport pinned into that preview set when needed), while the approaches mode shows the selected airport summary, a `Change Airport` affordance, and the procedures for the current airport. Choosing an airport automatically switches the panel into `Approaches`, and choosing an airport or approach still dismisses the keyboard. The airport filter disables autocorrect/auto-capitalization. The Layers panel toggles `approach`, `airspace`, `ADS-B Traffic`, and `MRMS Volume`, the Options panel includes the same ADS-B controls currently exposed on the web client (`Hide Ground Traffic`, `Show Traffic Callsigns`, `Hide Ground Callsign Labels`, `Traffic History`, `Show Departed Traffic Trails`) plus vertical scale, and the Debug FAB opens a Metal render-stats panel instead of keeping the stats overlay permanently visible. The panel surface is a rounded ultra-thin-material SwiftUI card with an internal `ScrollView`, so the Metal scene remains interactive around the visible panel without a UIKit passthrough host.
- On macOS, the shared SwiftUI shell now also exposes native menu commands and keyboard shortcuts for panel toggles (`Cmd-1` through `Cmd-4`), previous/next approach stepping (`Cmd-[` / `Cmd-]`), vertical-scale adjustments (`Cmd--` / `Cmd-=`), ADS-B traffic visibility (`Cmd-T`), and MRMS weather visibility (`Cmd-Shift-W`), and actionable controls opt into a pointing-hand cursor on hover.
- The native scene now renders edge-to-edge without the old split-view sidebar/list chrome. The in-scene header chip shows the airport ID plus the currently selected approach ID in a smaller secondary style, with a compact subtitle, and tapping that chip opens the selectors panel.
- `crates/approach-viz-core` has an `ios` feature with UniFFI exports for coordinate/projection math; `scripts/build-ios-bridge.sh` builds Apple targets, generates Swift bindings, and emits `ios/ApproachViz/RustBridge/Generated/ApproachVizCoreFFI.xcframework` with iPhoneOS, arm64 iOS Simulator, and universal macOS (`arm64` + `x86_64`) slices. The iOS project excludes `x86_64` simulator builds. The bridge script now fails immediately with a clear setup error when the active developer directory points at Command Line Tools instead of a full Xcode install, or when the iPhoneOS or macOS SDK is unavailable.

That lets building directly from Xcode recover from a cleaned `ios/ApproachViz/RustBridge/Generated` directory instead of failing immediately on a missing XCFramework reference, without introducing an Xcode build-graph cycle on the generated bridge files.
- `scripts/build-ios-app.sh` now fingerprints the Rust bridge inputs (`Cargo.lock`, `crates/approach-viz-core`, and `tools/uniffi-bindgen-swift`) and the XcodeGen spec (`ios/project.yml`), only rebuilding the UniFFI XCFramework or regenerating `ios/ApproachViz.xcodeproj` when inputs change or outputs are missing. `npm run build:ios:force` bypasses that incremental cache. The script still preserves a previously selected local `DEVELOPMENT_TEAM` from the existing project file across regenerations, and now fails immediately with a Homebrew install hint when `xcodegen` is unavailable.

The helper also foregrounds the chosen device in Simulator via `-CurrentDeviceUDID` so the app loop does not drift onto a different previously selected simulator.

- `npm run open:ios` and `npm run dev:ios` now use a project-only bootstrap path that skips the Rust bridge/data prerequisite work and only ensures the Xcode project exists before opening Xcode (and Simulator for `dev:ios`).

The helper additionally filters the remaining known `appintentsmetadataprocessor` warning line from upstream Swift package frameworks while preserving real build/test failures.
- `npm run test:ios` now performs `xcodebuild build-for-testing` followed by `test-without-building`, including the `ios/ApproachVizSnapshotTests` target. The helper script's simulator auto-detection tolerates Xcode 26's trailing-space `simctl` output, ignores devices stuck in `Creating`, boots a concrete iPhone simulator destination before both `xcodebuild` phases, and prints recent CoreSimulator log hints when no usable simulator can be created or booted.
- When deeper native automation is needed beyond shell-driven build/test/run loops, prefer the Build iOS Apps plugin's `ios-debugger-agent` / XcodeBuildMCP flow for scheme discovery, simulator UI interaction, screenshots, and simulator log capture once `ios/ApproachViz.xcodeproj` exists.
- Native iOS test coverage now includes `SnapshotTesting` snapshots and reducer-style `TestStore` coverage under `ios/ApproachVizSnapshotTests/`.
- Worker-first execution: approach altitude resolution and path/hold geometry, MRMS decode/prepare, traffic ingest/merge/recompute, selector filtering, and chart tile streaming run in workers via Comlink typed proxies; no synchronous compute fallback. The approach worker is a thin WASM adapter over the shared Rust engine, and its output arrays transfer to the main thread via `Comlink.transfer()` (zero-copy).
- ADS-B overlay polling: initial full-history query on context reset (`historyMinutes`), then live-only primary polls plus targeted `historyHexes` follow-up backfill when departed trails are enabled.
- ADS-B runtime payloads with `error` metadata are treated as poll failures in the traffic worker (no silent empty merge), and traffic worker request timeout budget is `12s`.
- ADS-B history-backfill follow-up failures no longer disappear silently: the web traffic worker surfaces `historyBackfillError` through the worker result into the traffic debug panel, and the native iOS `TrafficService` logs the failure and keeps the affected hexes pending so the next poll retries them.
- The `/api/traffic/adsbx` proxy validates query params before forwarding: present-but-malformed `radiusNm`/`limit`/`historyMinutes` return 400, finite out-of-range values are clamped to the runtime bounds, `format` must be a known value, and `historyHexes` entries must be hex identifiers (max 400). The Rust runtime applies the same reject-malformed/clamp-out-of-range policy and also rejects non-finite lat/lon (`NaN` included) on weather and traffic endpoints.
- The runtime HTTP router applies a 30s per-request `TimeoutLayer` (504 on expiry), and the weather volume/echo-tops handlers clone the latest scan `Arc` and release the snapshot read lock before FlatBuffers encoding so ingest writers are never blocked by slow queries. CPU-heavy runtime paths run on the Tokio blocking pool instead of async workers: per-request volume/echo-tops window filtering + FlatBuffers encoding, and MRMS scan snapshot assembly during ingest (per-level filter/gather/phase passes, full-grid echo-top scan with a no-signal fast skip, and counting-sort tile grouping).
- MRMS client rendering uploads voxel instance colors from precomputed per-phase dBZ band LUTs written directly into `instanceColor.array`, writes echo-top instance matrices directly into `instanceMatrix.array`, and receives the debug-panel phase tally from the MRMS worker result instead of recomputing it on the main thread. The web WASM binding (`decode_and_prepare_mrms`) now returns flat render-ready voxel columns (centers/sizes/dbz/phase) plus altitude-guide extents from the shared Rust `build_render_volume` join — the same path the native app uses — so per-instance uploads, per-instance alpha, and guide extents are addressed by instance index alone and the `declutterIndices` → `validIndices` → payload-column pairing no longer exists in TypeScript (mixing those index spaces previously lifted voxels onto higher layers' altitudes whenever the intensity filter skipped voxels; the join and its regression tests live in `crates/approach-viz-core/src/mrms_render.rs`). The worker's volume payload is now metadata-only (timestamps, layer summaries, voxel count, phase debug headers); raw per-voxel payload columns are not shipped to the main thread.
- The WASM AVMR/AVET decoders validate FlatBuffers column presence and length once at view construction, so the per-voxel prepare/cross-section/render-join loops carry no Option or length handling; a missing or length-mismatched column fails the poll with an explicit error instead of zero-filling or trapping.
- Runtime traffic "current aircraft" staleness window is `60s` (`CACHE_CURRENT_STALE_MS`); responses expose stale/freshness markers via `x-approach-viz-traffic-stale-current` and `x-approach-viz-traffic-snapshot-age-ms` headers (proxy passthrough enabled), and JSON payloads include `staleCurrent` + `snapshotAgeMs`.
- Layer defaults (`DEFAULT_LAYER_STATE`): `approach`, `airspace`, `adsb`, `probsevere`, `guides` = on; `mrms`, `echotops`, `slice` = off.
- MRMS phase-mode default is `surface` (`Surface Precip Type`); `thermo` is optional.
- Surface modes are `terrain | satellite | map | 3dmap`; FAA approach plates are an independent overlay toggle (`?plate=on`), not a surface mode. Legacy URLs `?surface=plate` → `?surface=terrain&plate=on`, `?surface=3dplate` → `?surface=satellite&plate=on`.
- Map and 3D Map modes use FAA ArcGIS tile services (VFR Sectional, TAC, IFR Low Enroute, IFR High Enroute); chart type URL param is `?chart=vfr|tac|low|high` (omitted when VFR or not in map mode). TAC is a composite chart type: VFR Sectional tiles as base layer with Terminal Area Chart tiles overlaid on top (TAC tiles only exist over major terminal areas; outside coverage, sectionals show through).
- Chart tile layer uploads use an sRGB `THREE.Texture` source and sRGB `THREE.DataArrayTexture` destination during `copyTextureToTexture` to avoid gamma/double-encoding artifacts.
- Flat-map chart tile shader applies Three.js output color-space conversion on sampled array-texture texels so Map and 3D Map chart colors remain consistent.
- Service worker (`sw/service-worker.ts`, bundled via esbuild) uses Workbox `CacheFirst` + `ExpirationPlugin` for Terrarium elevation tiles (800 max) and FAA chart tiles (1200 max), with a custom handler for FAA plates (dynamic cycle-aware cache name). Google 3D Tiles use browser-native HTTP caching. `npm run build:sw` rebuilds `public/service-worker.js`; `dev` and `build` scripts run it automatically.
- Cross-origin isolation headers are enabled by default (`COOP: same-origin`, `COEP: require-corp`), configurable via `DISABLE_CROSS_ORIGIN_ISOLATION` and `CROSS_ORIGIN_EMBEDDER_POLICY`.
- Runtime Datadog OTLP tracing no longer emits a bare span `version` field from HTTP protocol; `service.version` is always a build-time stamped `<yyyymmdd.hhmmss>-<git_branch>-<git_sha>` with optional `-dirty` suffix. OCI remote deploy builds pass the local branch/SHA/dirty state explicitly so version stamping does not require a `.git` directory in the staged remote source tree.
- CI uses `npm run build:sw` + `npx next build` (not `npm run build`) to avoid triggering data download during CI. A separate manual-dispatch `macOS Native Tests` workflow (`.github/workflows/macos-native.yml`) runs `npm run test:macos` on demand; native builds remain excluded from required CI.
- ESLint enforces `typescript-eslint` recommended rules (plus `no-unused-vars` with `_`-prefix escapes); `npm run lint` is a real gate, not parse-only.
- `scripts/download-data.sh` pins the Class B/C/D airspace GeoJSON source to a specific commit of `drnic/faa-airspace-data` and validates each payload parses as GeoJSON before installing it; the CIFP parser fails loudly (throws) on malformed DMS coordinates instead of fabricating 0,0. The script authenticates its `api.github.com` release lookup with `GITHUB_TOKEN` when set (the macOS native workflow passes `github.token`) so shared CI runners do not hit anonymous rate-limit 403s; release-asset downloads stay unauthenticated because the signed CDN redirect rejects forwarded `Authorization` headers.
- Approach-path engine sources live in `crates/approach-viz-core/src/approach_path/` (split into `types`/`altitudes`/`geometry`/`holds`/`support` modules with the public API re-exported from the module root). Course-from-fix legs (`FA`/`FC`/`FD`/`FM`) project an outbound apex from the originating fix along the published course (distance from the leg for `FC`/`FD`, default fallback otherwise). A teardrop/course-reversal (course-from-fix outbound + a no-fix `CI`/`VI` intercept, for example `KDDC I14` `FLACK` at `OWENJ`) renders as a single smooth circular arc through the outbound fix and the outbound apex that rolls out tangent onto the final approach course at an interior point — one continuous curve with no straight outbound leg. The roll-out point is the tangent point of the circle with the course line (`course_reversal_rollout_point`), not the course fix itself; `build_arc_through_three_points` draws the arc from the outbound fix through the apex to that tangent point and the transition terminates there. The scene composition (web `app/scene/ApproachPath.tsx` + iOS `ApproachPathGeometry.swift`) appends the final approach's first course-carrying fix leg (the FAF/localizer leg) to a transition ending in `CI`/`VI` to supply the course; that appended leg is consumed by the reversal and not drawn as a separate inbound segment. As an engine fallback when no roll-out fix is available, a terminal `CI`/`VI` after a course-from-fix leg is completed as a single broad, continuous turn (its own wider radius band, not the tight `VI` heading-stub radius) plus a mirrored inbound leg, instead of dead-ending at a sharp spike/stub. A plain course-from-fix leg with no reversal still renders as a straight outbound segment instead of collapsing onto the fix.
- Web client top-level state is decomposed into hooks under `app/app-client/hooks/` (`usePersistedOptions`, `useSceneSelection`, `useSurfaceState`, `useServiceWorkerDebug`, `useUrlSync`) with shared option normalizers in `app/app-client/option-normalizers.ts`; `AppClient.tsx` is composition + derived view state only.
- Native SwiftUI panel components live under `ios/ApproachViz/App/Panels/` (selector/layers/options/debug panels, panel chrome, shared controls); `RootView.swift` keeps only the root scene view, title chip, and FAB layout.
- Native iOS terrain tile cache is LRU-bounded (128 decoded tiles, ~32 MB) and the Metal SDF text atlas resets and re-packs all currently needed labels when its texture fills instead of silently dropping new labels; `SceneRepository`'s initializer is throwing (no `try!` crash path on a missing/corrupt bundled database).
- Formatting/linting ignore repo-local `.tmp/**` generated artifacts so local Xcode derived data, scratch logs, and other transient workspace outputs do not contaminate `npm run format:check`, `npm run lint`, or CI parity checks.
